Implement support for **Hofer** in the current repository and current branch, following existing project conventions.

## Scope

1. **Collector implementation**
   - Add a Hofer collector under `./data-collector/stores`.
   - Use the Hofer implementation from `heissepreise` as functional reference so it works equivalently, but **prioritize this repo’s collector conventions** when conflicts exist.
   - Reuse shared collector utilities where applicable.
   - Follow existing field contract/normalization behavior by mirroring other collectors in this repo.
   - ID strategy must follow how existing collectors in this repo handle IDs (no custom new scheme unless required by existing patterns).

2. **UI integration**
   - Integrate Hofer in `./dashboard` so it appears and behaves like other stores in:
     - store picker/filter
     - footer
     - header statistics line
   - Use default store metadata/display behavior used by existing stores.
   - No feature flag; Hofer should be visible by default.

3. **Runtime behavior / error handling**
   - Fetch cadence and operational behavior should match other stores.
   - Add reasonable fallbacks/error checks where appropriate.
   - If Hofer endpoint/collector fails, the run should **fail** (not warn-and-continue).

4. **Documentation**
   - Update root `README` only as needed.
   - No changelog/release note updates (no changelog exists).

## Explicitly out of scope

- Hofer-specific promo parsing/custom promo logic.
- Any special cross-store dedupe logic beyond existing project behavior.
- Any Hofer-specific price-history behavior beyond existing project behavior.
- Adding automated tests for this task.

## Definition of done

- Hofer collector runs without errors and returns products.
- Hofer appears correctly in dashboard UI (store picker/filter, footer, header statistics line), comparable to existing store integrations (same expectation as Alfies).
