Goal
Add a new store collector for **Alfies Graz** and integrate it into the existing data collection flow so Alfies Graz products are included in canonical output.

Scope
1. Create a new collector module:
   - `data-collector/stores/alfies-graz.js`
2. Use **public API endpoints if available and accessible without credentials**.
3. If no accessible API is available, fall back to storefront-based fetching.
4. Integrate collector into both:
   - `data-collector/index.js`
   - `data-collector/collect.js`

Store Identity
- `STORE`: **`alfies-graz`**
- Target storefront context: **https://alfies.shop/de/at/shop** (Graz)

Data Coverage
- Collect **all products** in Alfies Graz scope.
- **Include out-of-stock products**.

Canonical Mapping Requirements
Map to existing schema conventions used by current collectors:
- `id`: stable source product identifier
- `store`: `alfies-graz`
- `name`: required
- `price`: required numeric
- `priceHistory`: include today’s price entry
- `quantity` + `unit`: parse from source amount fields
- `bio`: map organic flag when available
- `url`: product detail URL when available (fallback to shop URL if missing)

Special rule:
- Do **not** store description text.

Error Handling
- Detect likely rate-limit / anti-bot responses (e.g. HTTP 429 or similar).
- Log via `console.warn` / `console.error`.
- Continue without crashing the full pipeline.
- No retry/backoff implementation required in this task.

Validation / Definition of Done
1. Standard collector flow runs without fatal errors.
2. `alfies-graz` is wired into fetch flow like other collectors (use velofood integration style).
3. Canonical output includes `alfies-graz` items with **non-zero** product count.
4. Required fields (`name`, `price`, `quantity`, `unit`, `bio` when available, `url` when available) are mapped correctly.

Out of Scope
- Credentialed/private API flows
- Retry/backoff strategy
- Extra enrichment beyond required schema mapping
